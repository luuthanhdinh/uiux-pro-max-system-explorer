## Design System: Developer API Docs

Generated from ui-ux-pro-max skill · Product: Developer Tools / API

### Pattern
- **Name:** Developer-First Landing + Docs + API Reference + Changelog
- **Sections:** 1. Landing (quick-start code), 2. Structured docs with sidebar, 3. API endpoint explorer, 4. Version changelog
- **CTA Placement:** Landing hero (Get API Key) + Docs sidebar (Try it) + API reference (copy button)
- **Conversion Focus:** Show working code in hero. Reduce time-to-first-API-call. Changelog builds trust.

### Style
- **Primary:** Minimalism & Swiss Style — strict grid, monospace code blocks, no decorative elements
- **Secondary:** Code-first UI — syntax-highlighted blocks, terminal aesthetic
- **Key Effects:** Code copy button on hover, endpoint method color coding, smooth sidebar navigation

### Typography
- **Heading:** JetBrains Mono (400/500/700) — signals developer-native product
- **Body:** Inter (300/400/500/600) — readable for long documentation
- **Code blocks:** JetBrains Mono at 13px, line-height 1.7
- **Google Fonts:** `https://fonts.google.com/share?selection.family=JetBrains+Mono:wght@400;500;700|Inter:wght@300;400;500;600`

### Anti-patterns
- Don't use Glassmorphism — wrong aesthetic for developer tools
- Avoid dark-mode-only design — many devs use light mode for docs
- Don't hide API endpoints behind marketing speak

| Docs | Onboarding | Sidebar nav, structured content, code examples |
| API Reference | Reference | Method/path list, request/response samples, status codes |
| Changelog | Trust | Semantic version labels, date, bullet change list |
